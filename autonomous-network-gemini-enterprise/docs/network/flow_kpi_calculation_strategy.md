# End-to-End Flow KPI Calculation Strategy

This document outlines how to calculate End-to-End Key Performance Indicators (KPIs) from the raw traffic metrics generated by the traffic agents. It uses the simulated tests deployed in the `telco-lab/traffic-tests` (Blue and Red VPNs) as practical examples.

---

## 1. Core Principles of Flow Metrics

Before calculating KPIs, it is critical to understand how the traffic-agent exports metrics to Prometheus:

*   **Roles:** A metric time series is tagged with a `role`. The `source` role represents the sender of the traffic, while the `destination` role represents the receiver.
*   **Directional Metrics:** Always prefer the directional gauges (`throughput_sent_bps` and `throughput_recv_bps`) over the legacy combined `throughput_bps` gauge.
*   **Bidirectional Flows:** Bidirectional tests create *two distinct flow IDs*. The forward flow retains the original name (e.g., `flow_id`), and the reverse flow appends a `_rev` suffix (e.g., `flow_id_rev`).
*   **Protocol Support:** TCP tests generate volume and throughput metrics. UDP tests generate volume, throughput, and performance quality metrics (latency, jitter, packet loss).

---

## 2. KPI Calculations

### 2.1 Actual Throughput (Bandwidth Delivery)
To evaluate if a flow is successfully achieving its target bandwidth across the network:

*   **Outbound Throughput (Speed Leaving Source):**
    *   **Metric:** `traffic_agent_throughput_sent_bps`
    *   **Filter:** `role="source"`
*   **Inbound Throughput (Speed Arriving at Destination):**
    *   **Metric:** `traffic_agent_throughput_recv_bps`
    *   **Filter:** `role="destination"`
*   **Throughput Discrepancy (Packet Drop Proxy):**
    *   Comparing Outbound vs Inbound throughput reveals network drops. If Outbound is significantly higher than Inbound, the network is congested and actively discarding traffic in transit.

### 2.2 Network Quality (Latency, Jitter, Packet Loss)
*Note: These KPIs are only available for UDP tests. The receiver calculates them using sequence numbers and timestamps embedded in the packets.*

*   **One-Way Delay (Latency):**
    *   **Metric:** `traffic_agent_latency_ms`
    *   **Filter:** `role="destination"`
*   **Jitter (Latency Variance):**
    *   **Metric:** `traffic_agent_jitter_ms`
    *   **Filter:** `role="destination"`
*   **Packet Loss:**
    *   **Metric:** `traffic_agent_packet_loss_pct`
    *   **Filter:** `role="destination"`

## 3. Examples: Telco-Lab Traffic Tests

### Example A: Blue VPN (Hub-and-Spoke, Consumer Traffic)

The Blue VPN simulates consumer cell backhaul traffic with a heavy hub-and-spoke design.

#### Test 1: TCP Bidirectional (e.g., `d1-hub-bidir-tcp`)
This flow simulates consumer uploads (forward) and video/content downloads (reverse).

*   **KPI: Spoke (d1) Upload Throughput**
    ```promql
    traffic_agent_throughput_sent_bps{flow_id="d1-hub-bidir-tcp_d1-blue", role="source"}
    ```
*   **KPI: Spoke (d1) Download Throughput (Reverse Flow)**
    ```promql
    traffic_agent_throughput_recv_bps{flow_id="d1-hub-bidir-tcp_d1-blue_rev", role="destination"}
    ```

#### Test 2: UDP Bidirectional (e.g., `d2-hub-bidir-udp`)
This flow simulates UDP streaming quality and push updates, exposing quality metrics.

*   **KPI: Hub-to-Spoke Packet Loss (Reverse Flow)**
    ```promql
    traffic_agent_packet_loss_pct{flow_id="d2-hub-bidir-udp_d2-blue_rev", role="destination"}
    ```

#### Test 3: UDP Unidirectional Aggregate (`all-spokes-hub-udp`)
This probe drives aggregate inbound load to the hub from all 3 spokes simultaneously.

*   **KPI: Total Probe Inbound Throughput at Hub**
    ```promql
    sum(traffic_agent_throughput_recv_bps{flow_id=~"all-spokes-hub-udp_.*", role="destination"})
    ```

### Example B: Red VPN (Full Mesh, Enterprise Traffic)

The Red VPN simulates business enterprise traffic flowing in an any-to-any mesh topology.

#### Test 1: TCP Cross-Site Replication (e.g., `d2-red-d3-red-bidir`)
Models batch jobs and database replication between branch sites.

*   **KPI: d2 to d3 Replication Speed (Forward)**
    ```promql
    traffic_agent_throughput_recv_bps{flow_id="d2-red-d3-red-bidir_d2-red", role="destination"}
    ```
*   **KPI: d3 to d2 Result-set Speed (Reverse)**
    ```promql
    traffic_agent_throughput_recv_bps{flow_id="d2-red-d3-red-bidir_d2-red_rev", role="destination"}
    ```

#### Test 2: UDP VoIP/Video-Conferencing (e.g., `d1-red-d4-red-bidir`)
Models symmetric real-time communication where latency and jitter are critical.

*   **KPI: VoIP Latency (d1 to d4)**
    ```promql
    traffic_agent_latency_ms{flow_id="d1-red-d4-red-bidir_d1-red", role="destination"}
    ```
*   **KPI: VoIP Jitter (d4 to d1)**
    ```promql
    traffic_agent_jitter_ms{flow_id="d1-red-d4-red-bidir_d1-red_rev", role="destination"}
    ```
