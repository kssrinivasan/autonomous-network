Heterogeneous Graph Neural Network

A spatial graph autoencoder that monitors a live telecommunications network in real time, learns the topology's healthy baseline, and flags nodes that deviate using Mahalanobis distance scoring in embedding space.

Embedding Generation & Mahalanobis Anomaly Scoring

Each node's 64-d embedding is a graph-contextualised representation: it encodes not just the node's own telemetry but the state of its neighborhood across multiple hop levels and all 11 edge relation types (physical links, control-plane adjacencies, VPN membership, traffic flows).

Message-Passing (per layer)

hi(k) = σ( W·MEAN{ hj(k-1) | j∈N(i) } + B·hi(k-1) ) + Dropout

Nodes with no incoming edges for a given relation retain their previous-layer embedding unchanged — they are not zeroed out.

Post-Training Calibration

After training, all training snapshots are re-encoded in eval mode. For each node type the following healthy-state statistics are computed and saved to model_stats.pth:

  • Centroid μ ∈ ℝ⁶⁴
  • Covariance Σ ∈ ℝ⁶⁴ˣ⁶⁴
  • Regularised inverse Σreg⁻¹ = (Σ + εI)⁻¹ with ε = 10⁻⁵ (ridge term for VPN's near-singular N=3 covariance)
  • Healthy training D_M distribution: mean, std, max

Mahalanobis Distance (serve time)

DM(zi) = √( (zi − μ)T Σreg⁻¹ (zi − μ) )

Threshold Calibration Formula

thresholdtype = max( D̄M + K·σD_M, DMmax × FLOOR_MULTtype )
ParameterValueRationale
K (MAHA_K)2.0~95th percentile of a Gaussian — catches single-feature faults like vrf-rt-misconfiguration where only one PE's embedding shifts modestly
FLOOR_MULT router1.2×PE2 hub and CE/RR routers sit structurally far from the population centroid; live healthy D_M for PE2 routinely exceeds mean+2σ
FLOOR_MULT interface1.2×Route-reflector loopbacks and hub-side links diverge from the bulk for structural reasons
FLOOR_MULT vpn1.5×N=3 unique VPN nodes; empirical mean+2σ is artificially tight (within-node temporal variance, not across-population)
FLOOR_MULT flow1.2×Per-flow KPIs drift with traffic conditions; pure mean+2σ on a 3h window underestimates serving variance

Why Mahalanobis over Per-feature MSE

CriterionMSE (per-feature)Mahalanobis (embedding)
Accounts for feature correlations No — each feature independent Yes — Σ⁻¹ captures correlated drift
Sensitive to small multi-feature shifts No — diluted across all dims Yes — any principal-direction shift detected
Stable for small-N types (VPN, N=3) No — decoder variance dominates Yes — encoder embeddings are more stable
Interpretability Direct — which raw feature is anomalous Indirect — top-3 MSE features added for attribution
Design principle The anomaly flag is always driven by D_M. Per-feature reconstruction MSE is computed after the fact, purely to generate a human-readable "top-3 contributing features" explanation for the network operator. The two signals are intentionally decoupled.

Loss Function

ℒtotal = 0.25·ℒrouter + 0.25·ℒinterface + 0.25·ℒvpn + 0.25·ℒflow + 0.10·ℒdiversity
Per-type reconstruction loss
MSE between decoder output x̂ᵢ and original input xᵢ. Equal weights (0.25 each) ensure VPN nodes — despite only N=3 per snapshot — receive the same gradient signal as routers and interfaces.
Contrastive diversity loss
Penalises mean pairwise cosine similarity within each node type's embedding batch. Prevents representation collapse — forces the model to produce distinct embeddings for structurally different nodes.

Training Pipeline — Vertex AI Pipelines (KFP v2)

The full training lifecycle is orchestrated as a Kubeflow Pipelines v2 DAG submitted to Vertex AI. Triggered via ./install.sh --deploy gnn. A quality gate prevents automatic deployment of models with validation loss > 1.0.

1
Ingest Snapshots
Fetches 360 snapshots from Spanner (30 s cadence = 3 h window). Parallelised via ThreadPoolExecutor(8 workers) — reduced from 60 min → 3-4 min. Serialises to GCS as .pkl files per snapshot.
n1-standard-4 GCS output
2
Fit Scalers
Fits one StandardScaler per node type over all ingested snapshots. Router scaler covers 13 continuous features (indices 0–12); role one-hot columns are excluded. Inactive flows (all-zero traffic metrics) are filtered before fitting. Saves scalers.pkl to GCS.
GCS output
3
Train Model
Launches a Vertex AI Custom Training Job running train_hetgnn.py. Trains HetGNN (up to 50 epochs, early-stopping patience 10), then runs post-training calibration to compute Mahalanobis cluster statistics. Saves model.pth + model_stats.pth to GCS.
Vertex AI Custom Job GCS output
4
Evaluate Model
Scores the trained model on the held-out 20% validation set. Emits a scalar val_loss used by the quality gate. Pipeline logs per-task states — a passing pipeline (SUCCEEDED) can still have undeployed steps if val_loss > 1.0.
QG
Quality Gate
Steps 5–7 are conditionally triggered only when val_loss < 1.0. If the condition is not met, the pipeline still reports SUCCEEDED but steps show as NOT_TRIGGERED and no deployment occurs.
dsl.Condition(val_loss < 1.0)
5
Register Model
Registers model artifacts + serving image to Vertex AI Model Registry as a new versioned gnn-hetgnn entry.
Vertex AI Model Registry
6
Deploy Endpoint
Deploys the new model version to the gnn-endpoint Vertex AI Endpoint, shifting 100% traffic to the new deployed model. Model artifacts are referenced via AIP_STORAGE_URI — no manual manifest update needed.
Vertex AI Endpoint
7
Update Inference Scheduler
Updates Cloud Scheduler gnn-inference-scheduler to target the newly deployed endpoint.
Cloud Scheduler
7

Serving Workflow — Every 60 Seconds

Trigger
Cloud Scheduler * * * * *
Server
Vertex AI Endpoint · Cloud Run · aiohttp
Model Cache
In-process _cache dict — warm across requests
  1. Receive POST /predict with timestamp from Cloud Scheduler.
  2. Load model weights, scalers, and cluster statistics from GCS (path from AIP_STORAGE_URI env var, set by Vertex AI at deploy time). Cached in-process after first load.
  3. Fetch the network snapshot at the given timestamp from Spanner (networktopology-db) — routers, interfaces, VPNs, flows, VRF configs.
  4. Build a HeteroData graph object via GraphBuilder using the calibrated scalers.pkl.
  5. Run HetGNN forward pass → node embeddings zᵢ ∈ ℝ⁶⁴ and reconstruction vectors x̂ᵢ.
  6. For each node, compute D_M(zᵢ) using pre-computed μ and Σ_reg⁻¹ from model_stats.pth.
  7. Flag node as anomalous if D_M(zᵢ) > thresholdtype. Compute per-feature MSE breakdown to identify top-3 contributing features (attribution only).
  8. Write node embeddings, D_M scores, anomaly flags, and feature attributions to Spanner NodeEmbedding table. Return JSON summary to caller.
Fallback compatibility For model artifacts trained before Mahalanobis scoring was introduced (no cluster_stats key in model_stats.pth), serve.py falls back to per-feature reconstruction MSE with hardcoded thresholds, ensuring backward compatibility.
